# Onevoke 基础规则

## 适用范围与优先级

- 跨项目通用条款, 装在 `~/.agents/BASE-RULES.md`. 入口 `~/.agents/ONEVOKE-AGENTS.md` 列出全部分册并定义规则优先级; 本机工具选择由 Onevoke 配置保存.
- 每个任务开始时读本文件. 分册索引和完整优先级链见入口.
- 本文件与入口「默认取值」冲突时从入口; 与其他分册的领域条款冲突时从那份分册.
- 同目录 `AGENTS.md` 与 `CLAUDE.md` 冲突且用户指令未消解时, 停止受影响操作, 问用户.
- 「Git 工作流」及其分册只适用 Git 仓库. 非 Git 目录无分支, worktree, 审核, 集成, 直接改文件.

## 交流与格式

- 对话, 文档, 代码注释, 提交消息默认中文; 项目规则另有要求从项目规则.
- 自然语言用 ASCII 标点, 中英之间留一空格. 代码符号, API 名, 原始错误文本原样.
- 图表和表格只用 ASCII. 宽度不超 100 英文字符或约 50 汉字; 超出则换行, 拆表或改列表.
- 让用户选项时, 从 `1` 编号, 每项写清动作和结果; 用户只回编号即有效.

## 工作原则

### 范围与复用

- 选最小且可证实方案. 分析架构, 边界情况, 根因; 不用口号代替证据.
- 新增功能前先查既有功能和可复用组件; 优先复用或扩展现有实现, 避免重复代码.
- 匹配周边文件风格, 不重排, 格式化或重构无关代码.
- 不覆盖, 回退或清理用户已有改动. 用户改动阻塞切分, 验证或集成时, 保留现场并报告.

### 架构与代码质量

- 完整规则见 `~/.agents/CODE-RULES.md`; 改代码前先读取该文件并遵循. 只改文档或配置不涉及代码时可跳过.

### 规则沉淀

- 项目架构, API 或长期规则稳定后写入仓库文档或对应 `AGENTS.md`, 禁只存记忆.

## 记忆管理

- 本节只在用户已完成 MemSearch 接入并在 Onevoke 配置中选择启用时适用. Onevoke 不检查 CLI、插件或 hook 状态; 安装和故障由用户自行处理.
- 适用时 `memsearch` 为唯一记忆系统. 会话流水由当前 Agent 的 hook 自动写入 `.memsearch/memory/*.md`; 不手写记忆文件, 不手动跑 `memsearch index`.
- 任务完成, PR 合并或阶段目标完成时, 确认自动记录含任务摘要, 关键决策, 适用 commit hash. 记录缺失只报告用户, 不自行补写.
- 确认记录完整后提示用户: "建议开新会话, 历史已存 memsearch".

## 探索, 编辑与验证

- monorepo 命令按仓库文档和脚本指定工作目录运行. 子项目命令从对应子项目目录跑; 根级编排命令从仓库根跑.
- 改后跑能直接证明改动的最小验证. 测试或环境失败时记录实际命令和错误, 禁标为通过; 既有环境故障同样处理. 错误含敏感值时该值换 `[REDACTED]`, 其余文本原样.

## 用户维护文件

- 项目规则声明为用户手动维护的文件, agent 禁改其内容. 处理已有改动遵循项目规则; 未声明则保留现场, 禁复制, 移动或混入任务提交.
- Git 仓库开始任务时检查当前工作树; 建任务 worktree 前还须检查主树.

## Git 工作流

- 完整规则见 `~/.agents/GIT-RULES.md`; 建分支, 提交, push, 审核或集成前先读取该文件并遵循.

## 安全

- 凭据只能经环境变量, secret manager 或仓库约定的 gitignored secret 文件注入.
- 禁把真实 token, 凭据, 敏感服务地址或本机状态写入仓库, 日志, 测试 fixture, dry-run 或发布输出. 敏感服务地址和本机状态含未公开内网地址, 含敏感路径或参数的公开 endpoint, 本机专属路径, 机器标识.

## 任务完成

- 每个任务结束时, 一句话总结任务目标, 完成情况, commit 状态和所在分支; 非 Git 任务明确写 "无提交, 分支不适用".
- 看板任务改用 `~/.agents/KANBAN-RULES.md`「完成报告」的模板汇报.
